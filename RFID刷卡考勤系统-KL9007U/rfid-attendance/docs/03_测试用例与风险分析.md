## 第二部分：风险分析

| 编号 | 风险 | 概率 | 影响 | 应对措施（已实现） | 代码位置 |
|---|---|---|---|---|---|
| R1 | **通信不稳定**：读写器掉线、串口被占用、半截帧/CRC 错帧 | 高 | 高 | ① 后台线程 try/except + 自动重连；② 帧长 + CRC 双重校验，非法帧丢弃；③ 握手命令确认在线；④ 提供"读卡诊断"工具定位 | `CardReaderThread.run()`、`split_frames()`、`读卡诊断.py` |
| R2 | **重复打卡**：卡一直放在天线上被反复读到 | 高 | 中 | 读卡层去抖（同卡 `debounce_seconds` 内只上报一次且续期）+ 业务层再判一次 `DUPLICATE` | `CardReaderThread`、`AttendanceService.handle_card()` |
| R3 | **卡号伪造 / 代刷**：拿别人的卡或复制标签 | 中 | 高 | ① 卡号与学生唯一绑定（`students.card_no UNIQUE`）；② 可切换"读 TID"（TID 出厂唯一、难复制）作为卡号；③ 记录每次刷卡时间，异常时段可人工核查 | 设置项 `use_tid`；`students.card_no UNIQUE` |
| R4 | **数据丢失 / 篡改**：记录被误删、改学生后历史丢失 | 中 | 中 | 打卡记录以快照方式冗余学号/姓名/班级；删除学生不级联删记录 | `attendance` 表快照字段；`delete_student()` |
| R5 | **硬件/驱动问题**：没装 USB 转串口驱动、波特率不匹配 | 高 | 中 | 开发包附带驱动；程序内置"自动探测波特率×地址"；设置项可调 | `读卡诊断.py._probe_all()` |
| R6 | **环境缺失 / 依赖装错解释器**：机房电脑多只 Python 共存，`pip install pyserial` 只装进其中一只，程序却被另一只启动 → 出现"明明装了却提示没装" | 中 | 中 | ① `try/except` 导入，缺失时降级为键盘模式并有明确提示；② **把 pyserial 整个内置到 `_vendor/serial`**，`import serial` 失败自动改从 `_vendor` 加载，任何 Python 都能用，免联网免安装；③ 设置页显示"当前实际使用的 Python 路径 + 串口库来源"；④ 提供 `环境自检.bat` 一次列出每只 Python 的 tkinter/pyserial/串口状况；⑤ 设置页提供「重新检测依赖」与「一键安装 pyserial」 | `attendance.py._import_serial()`、`uhf_reader.py._import_serial()`、`env_check.py`、`环境自检.bat` |
| R7 | **数据量膨胀**：记录越来越多查询变慢 | 低 | 低 | 按天建索引；查询默认 limit；提供按日期过滤 | `SCHEMA_SQL` 索引；`query_records()` |
| R8 | **时间被改**：系统时间不准导致签到签退判定错 | 低 | 中 | 判定基于本机时间；建议考试机校时（可扩展为 NTP 校时） | — |

### 风险应对优先级

1. **P0**：R1 通信不稳定、R2 重复打卡 —— 直接影响能否成功刷卡，已重点处理（重连 + 双层去抖 + CRC 校验）。
2. **P1**：R3 卡号伪造、R4 数据丢失 —— 用唯一绑定 + 快照冗余缓解。
3. **P2**：其余 —— 通过配置项与提示引导规避。
