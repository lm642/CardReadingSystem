RFID 一卡通刷卡考勤系统 · 系统设计文档

基于 KL9007U 超高频(UHF)读写器的学生签到 / 签退系统　·　软件工程课程分组项目

Python 3.8+ tkinter 界面 SQLite 数据库 pyserial 串口 UHFReader18 协议

一、系统概述

本系统用 UHF RFID 读写器实现"刷卡即考勤"：学生拿标签卡在天线上刷一次完成签到， 再刷一次完成签退，记录自动入库并可查询导出。

核心难点：KL9007U 是超高频读写器，工作在「应答模式」——它不会主动 往串口输出卡号，必须由上位机按 UHFReader18 协议主动发命令去读标签。 因此系统必须先实现协议层（组帧 / CRC 校验 / 询查 / 响应解析），这也是本项目与普通"串口读卡 demo"的本质区别。

三、通信协议（UHFReader18）

3.1 命令帧结构

Len
1 B
Adr
1 B
Cmd
1 B
Data[]
0 ~ 最多 92 B
CRC-L
1 B
CRC-H
1 B

Len = Data 长度 + 4（不含 Len 本身）。读写器应答帧在此基础上多一个 reCmd 与一个 Status 字节。

3.2 CRC-16 校验

crc = 0xFFFF                     # 初值 PRESET_VALUE
for b in data:                   # data 范围：从 Len 到 Data 的全部字节
    crc ^= b
    for _ in range(8):
        crc = (crc >> 1) ^ 0x8408 if (crc & 1) else (crc >> 1)
# 结果低字节先发：CRC-L, CRC-H

多项式 0x8408、初值 0xFFFF、无输出异或（等价 CRC-16/MCRF4XX）。

3.3 关键命令与帧示例（读写器地址 0x00）

命令含义命令帧（十六进制）
0x01询查（读取 EPC，即卡号）04 00 01 DB 4B
0x01 02 04询查 TID（起始字 2，读 4 个字）06 00 01 02 04 58 24
0x21读取读写器信息（握手）04 00 21 D9 6A
0x20设置波特率（03 = 57600）05 00 20 03 DE 7C

3.4 询查响应解析

响应 Data 段格式：[标签个数 Num][EPC长度1][EPC1][EPC长度2][EPC2]…

# 例：Data = 01 06 00 11 58 23 00 00
#   Num = 1，EPC 长度 = 6，EPC = 00 11 58 23 00 00
#   卡号(十六进制字符串) = "001158230000"
脏数据过滤（三道防线）： ① 帧层：长度非法或 CRC 不通过 → 丢弃（split_frames）； ② 卡号层：去控制符/分隔符、统一大写，非 4~32 位十六进制 → 丢弃（normalize_card）； ③ 业务层：重复卡、陌生卡、非法文本 → 不写入有效记录。

四、系统架构（分层）

协议驱动层 · uhf_reader.py

组帧 / CRC / 收发 / 切帧 / 解析；后台读卡线程（询查 + 去抖 + 断线重连）。

业务逻辑层 · AttendanceService

签到 / 签退判定、30 分钟间隔、防重复、陌生卡处理。

数据访问层 · Database

SQLite 建表与全部 SQL（students / attendance / unknown_cards / settings）。

界面层 · AppUI (tkinter)

打卡台 / 历史记录 / 学生管理 / 设置 / 使用说明；经 queue 与线程通信。

九、数据库设计

students 学生表

id PK · student_no UNIQUE · name · class_name · card_no UNIQUE · created_at

attendance 打卡记录表

id PK · student_id · student_no/name/class_name(快照) · card_no · action(in/out) · ts · day

unknown_cards 陌生卡日志

id PK · card_no · ts

settings 配置表

key PK · value（interval_minutes / serial_port / serial_baud / debounce_seconds …）

主键设计：统一用自增整型 id 作代理主键，业务唯一性用 UNIQUE 约束 （student_no、card_no）；打卡记录冗余学生信息作快照， 学生改名/删除后历史仍完整。索引：day、(student_id, day)、card_no。

十、测试与风险摘要

自动化测试

  • ✔ 业务逻辑 14 条：attendance.py --selftest
  • ✔ 协议层 9 条：python uhf_reader.py
  • 覆盖：脏数据 / 重复刷卡 / 间隔不足 / 陌生卡 / 串口异常 / 粘包 / 半包

主要风险与应对

  • 通信不稳 → 握手 + 自动重连 + 帧长/CRC 双校验
  • 重复打卡 → 读卡层 + 业务层双层去抖
  • 卡号伪造 → 卡与学生唯一绑定；可切换读 TID
  • 数据丢失 → 打卡记录快照冗余
