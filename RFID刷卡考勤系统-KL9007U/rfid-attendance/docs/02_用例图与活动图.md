## 1. 用例图

参与者：**学生**（刷卡）、**教师/管理员**（管理学生、查记录、配置）；
外部系统：**KL9007U 读写器**（被系统驱动）。

```mermaid
graph LR
    Student(["学生"])
    Admin(["教师 / 管理员"])
    Reader(["KL9007U 读写器"])

    subgraph SYS["RFID 刷卡考勤系统"]
        UC1(("刷卡签到"))
        UC2(("刷卡签退"))
        UC3(("查询历史记录"))
        UC4(("导出 CSV"))
        UC5(("学生信息管理"))
        UC6(("刷卡绑定卡号"))
        UC7(("系统设置"))
        UC8(("读卡诊断"))
        UC9(("异常提示与留痕"))
    end

    Student --> UC1
    Student --> UC2
    Admin  --> UC3
    Admin  --> UC4
    Admin  --> UC5
    Admin  --> UC6
    Admin  --> UC7
    Admin  --> UC8

    UC1 -. "<<extend>>\n陌生卡/重复卡/间隔不足" .-> UC9
    UC2 -. "<<extend>>\n陌生卡/重复卡/间隔不足" .-> UC9
    UC1 -. "<<include>>\n读卡" .-> Reader
    UC2 -. "<<include>>\n读卡" .-> Reader
    UC6 -. "<<include>>\n读卡" .-> Reader
```

**用例说明**

| 用例 | 前置条件 | 基本流 | 备选流 |
|---|---|---|---|
| 刷卡签到 | 卡已绑定学生 | 刷卡→读卡→首次打卡→写库(action=in)→提示成功 | 陌生卡/重复卡/脏数据 |
| 刷卡签退 | 当天已签到且间隔足够 | 刷卡→读卡→判定为签退→写库(action=out)→提示成功 | 间隔不足→提示还需等待 |
| 学生信息管理 | 已登录界面 | 增删改查学生，可刷卡自动填卡号 | 学号/卡号重复→提示 |
| 系统设置 | — | 修改间隔/串口等参数并保存 | 非法数值→回退默认 |

## 2. 活动图：完整的"刷卡 → 判定"流程

这是最核心的一张图，对应 `AttendanceService.handle_card()`。

```mermaid
flowchart TD
    A([开始：读卡线程读到卡号]) --> B[normalize_card 归一化<br/>去控制符/分隔符，统一大写]
    B --> C{is_valid_card?<br/>4~32 位十六进制}
    C -- 否 --> Z1[返回 BAD_DATA<br/>忽略，不入库]
    C -- 是 --> D{同一张卡在<br/>debounce 窗口内?}
    D -- 是 --> Z2[返回 DUPLICATE<br/>续期去抖计时器]
    D -- 否 --> E[按卡号查 students 表<br/>get_student_by_card]
    E --> F{查得到学生?}
    F -- 否 --> Z3[log_unknown 记录陌生卡<br/>返回 UNKNOWN，友好提示]
    F -- 是 --> G[查当天最后一条记录<br/>latest_record_of_day]
    G --> H{当天有记录吗?}
    H -- 无 --> I[action = in 签到]
    H -- 有且为 in --> J{距上次签到<br/>≥ interval 分钟?}
    J -- 否 --> Z4[返回 TOO_SOON<br/>提示还需等待多久]
    J -- 是 --> K[action = out 签退]
    H -- 有且为 out --> I
    I --> L[add_record 写库<br/>快照学号/姓名/班级]
    K --> L
    L --> M[界面显示结果 + 蜂鸣 + 刷新统计]
    M --> N([结束])
    Z1 --> N
    Z2 --> N
    Z3 --> N
    Z4 --> N
```

## 3. 活动图：串口读卡线程（协议层 + 容错）

对应 `uhf_reader.py: CardReaderThread.run()`。

```mermaid
flowchart TD
    S([线程启动]) --> O[打开串口 COM9 @ 57600 8N1]
    O --> O2{打开成功?}
    O2 -- 否 --> E1[提示异常<br/>等待 reconnect 秒] --> O
    O2 -- 是 --> H[发送 0x21 读读写器信息<br/>握手确认在线]
    H --> L[发送 0x01 询查命令]
    L --> R{收到响应帧?}
    R -- 否 --> E2[判定通信异常<br/>抛异常] 
    E2 --> E1
    R -- 是 --> P[split_frames 按帧长+CRC 切帧<br/>丢弃非法/半截帧]
    P --> Q[parse_inventory_payload 解析出 EPC 列表]
    Q --> T{该 EPC 在 debounce 窗口内出现过?}
    T -- 否 --> U[放入消息队列 queue<br/>通知界面线程] --> W
    T -- 是 --> W[等待 poll_interval 后继续下一轮]
    W --> L
```

## 4. 活动图：签到 / 签退状态机

同一天内，同一学生的状态迁移（简洁版，便于口头讲解）：

```mermaid
stateDiagram-v2
    [*] --> 无记录
    无记录 --> 已签到: 刷卡 → in
    已签到 --> 已签到: 刷卡但 < 30min（TOO_SOON，拒绝）
    已签到 --> 已签退: 刷卡且 ≥ 30min → out
    已签退 --> 已签到: 再次刷卡 → in（可多轮进出）
    已签退 --> [*]: 当天结束
```

## 5. 时序图：一次成功刷卡的完整交互

```mermaid
sequenceDiagram
    participant U as 学生
    participant D as 读写器(KL9007U)
    participant T as 读卡线程(CardReaderThread)
    participant B as 业务层(AttendanceService)
    participant DB as SQLite
    participant UI as 界面(tkinter)

    U->>D: 把卡放到天线上
    T->>D: 发送询查命令 04 00 01 DB 4B
    D-->>T: 响应帧(含 EPC)
    T->>T: CRC 校验 + 解析 EPC + 去抖
    T->>UI: 队列消息 ("card", EPC)
    UI->>B: handle_card(EPC)
    B->>DB: 查学生、查当天最后记录
    DB-->>B: 学生信息 / 上次记录
    B->>DB: 写入打卡记录(action)
    DB-->>B: 记录号
    B-->>UI: Result(成功, 学生, 动作, 时间)
    UI->>U: 大字提示 + 蜂鸣
```
