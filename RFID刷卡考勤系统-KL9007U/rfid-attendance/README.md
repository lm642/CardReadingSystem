# RFID 一卡通刷卡考勤系统（学生签到 / 签退）

> 软件工程课程分组项目 · 基于 **KL9007U 超高频(UHF)读写器** 的刷卡签到签退系统

---

## 1. 这是什么

一套"刷卡即签到 / 再刷即签退"的考勤系统，硬件是实训用的 **KL9007U UHF 读写器**。

核心特点：**读写器工作在"应答模式"**，不会主动吐卡号，程序必须按
UHFReader18 协议组帧、算 CRC、主动发"询查"命令去读标签 —— 这层协议逻辑
封装在 `uhf_reader.py`，是本项目区别于"抄个串口读卡 demo"的关键。

---

## 2. 硬件与连接

| 项目 | 值 |
|---|---|
| 读写器 | KL9007U（协议类型 UHFReader18，固件版本 02.31） |
| 接口 | USB 转虚拟串口（需装 CP210x / CH340 驱动，开发包内附带） |
| 串口 | **COM9**（以设备管理器实际为准） |
| 通信参数 | **57600 bps，8 数据位，1 停止位，无校验（8N1）** |
| 工作模式 | 应答模式（EPC C1G2） |
| 支持协议 | ISO18000-6C(EPC Gen2) / ISO18000-6B |
| 频率 | Chinese band2，920.125 ~ 924.875 MHz，功率 23 |
| 标签 | UHF 电子标签（如 EPC = `001158230000`、TID = `013902000083EA4C`） |

> ⚠️ 读写器同一时刻只能被一个程序占用。厂商演示软件 `UHFReader18CSharp` 开着时，
> 本程序会打不开串口 —— 请先关掉它。

## 3. 快速开始

**不需要装任何东西，直接双击就行。**

```bash
# 1. 一键读卡测试：确认硬件能读到卡（强烈建议先跑这一步）
python read_test.py

# 2. 启动图形界面主程序
python attendance.py
```

Windows 下直接双击：`读卡测试.bat`（硬件自测）、`启动程序.bat`（主程序）。

> **为什么不写 `pip install pyserial`？**
> 因为 pyserial 已经放在项目自带的 `_vendor/` 目录里了（内置依赖 / vendoring）。
> 程序启动时先 `import serial`，失败就自动把 `_vendor` 加到模块搜索路径再试一次。
> 这样**用哪个 Python 打开都能读到串口**，不用联网、不用 pip、不用管理员权限。
> 见 §5 问题 0 的真实踩坑记录。

**第一次使用**：进入「学生管理」页 → 「新增学生」→ 填学号姓名 →
点「绑定卡号（刷卡）」→ 把卡放天线上，卡号自动填入。

## 5. 常见问题（刷卡没反应怎么办）

### 问题 0（高频踩坑）：明明装过 pyserial，程序却说"未安装"

**原因**：一台电脑上往往装了多个 Python。`pip install pyserial` 只会装进**其中某一个**，
而程序可能是被**另一个** Python 启动的 —— 于是"装了"和"用上了"不是同一只 Python。

判断方法：看程序「设置」页的**运行环境自检**，它会显示程序**实际使用的 Python 路径**；
再双击 `环境自检.bat`，它会把这台电脑上每个 Python 的 pyserial / tkinter / 串口情况全部列出来。

**本项目怎么解决的**：把 pyserial 内置到 `_vendor/serial`，`import serial` 失败时自动改从
`_vendor` 加载（代码里是 `attendance.py` 的 `_import_serial()` 和 `uhf_reader.py`
的 `_import_serial()`）。所以**正常情况下根本不会出现这个错误**。

如果还是出现了，按顺序：
1. 确认项目是**完整解压**的（目录下必须能看到 `_vendor/serial` 文件夹）；
2. 「设置」页点 **🔄 重新检测依赖**；
3. 还不行动 **🛠 一键安装 pyserial（联网）**，它会给当前正在跑的这个 Python 装；
4. 跑一次 `环境自检.bat` 把结果发出来定位。

### 刷卡没反应的一般排查

按顺序排查：

1. **先跑 `python read_test.py`**，看能不能打印出读写器信息。
2. **串口对不对**：`python attendance.py --list-ports`，插拔读写器对比。
   本机实测读写器是 `COM9  USB-SERIAL CH340`（蓝牙那几个 COM 不用管）。
3. **波特率对不对**：KL9007U 默认 57600；不对可试 9600 / 19200 / 115200。
   用「读卡诊断」的「⚡ 自动探测」一键遍历波特率 × 地址。
4. **地址对不对**：出厂 0；读不到可在设置里改成 255（广播地址）。
5. **串口被占用**：关掉厂商演示软件 / 其他串口助手。
6. **驱动没装**：开发包里 `USB 驱动/CP210x_VCP_...exe`（本机是 CH340，装 `CH341SER.EXE`）。
7. **天线 / 供电**：确认天线接好、读写器指示灯正常。
8. 还不行 → 打开主程序「设置」页 → 「🔍 刷卡没反应？打开读卡诊断工具」。

## 6. 协议速查（答辩会用）

命令帧：`Len | Adr | Cmd | Data[] | CRC-L | CRC-H`（Len = Data 长度 + 4）

| 命令 | 含义 | 帧示例（地址 00） |
|---|---|---|
| `0x01` | 询查（读 EPC） | `04 00 01 DB 4B` |
| `0x01 02 04` | 询查 TID（起始字 2，读 4 字） | `06 00 01 02 04 58 24` |
| `0x21` | 读取读写器信息（握手） | `04 00 21 D9 6A` |
| `0x20` | 设置波特率 | `05 00 20 03 DE 7C`（03=57600） |

CRC16：多项式 `0x8408`，初值 `0xFFFF`，低字节在前，校验范围「Len → Data」。
验证：`python uhf_reader.py` 会跑协议层单元自检（帧、CRC、粘包切帧、响应解析）。
