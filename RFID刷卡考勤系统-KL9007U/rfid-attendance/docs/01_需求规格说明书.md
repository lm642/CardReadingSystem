# 01 需求规格说明书

**项目名称**：RFID 一卡通刷卡考勤系统（学生签到 / 签退）
**课程**：软件工程　**类型**：分组项目
**硬件**：KL9007U 超高频(UHF)读写器　**软件**：Python 3.8+ / tkinter / SQLite

> 说明：本说明书与代码逐条对应。每个功能需求后标注了实现位置（文件 + 函数/表名），
> 便于答辩时"从文档直接指到代码"。

---

## 1. 项目背景与目标

高校课堂/实训室考勤目前多靠人工点名或扫码，效率低、易代签。本项目使用 UHF RFID
读写器 + 电子标签实现"刷卡即打卡"，目标：

1. 学生拿卡在读写器上刷一次即完成签到，再刷一次即签退，无需人工干预；
2. 打卡记录自动入库，可查询、可导出；
3. 能应对陌生卡、重复刷卡、读写器掉线等异常，不崩溃。

**技术难点**（也是本项目的核心价值）：KL9007U 是 UHF 读写器，工作在
**应答模式**——不会主动输出卡号，必须由程序按 UHFReader18 协议主动发命令读取。
这一层协议通信是普通读卡器 demo 没有的。

## 2. 术语

| 术语 | 含义 |
|---|---|
| EPC | Electronic Product Code，电子标签的电子产品码，本项目用作"卡号" |
| TID | 标签唯一标识区，比 EPC 唯一性更强（部分标签支持读 TID） |
| 应答模式 | 上位机发命令、读写器回结果的通信模式（与"主动模式"相对） |
| 询查(Inventory) | 读写器命令，用于读取有效场内的标签 EPC |
| 签到/签退 | 学生一天的第一次刷卡记为签到，离开时刷卡记为签退 |

## 3. 功能需求（FR）

### FR-1 读卡（核心）
| 编号 | 需求 | 实现位置 |
|---|---|---|
| FR-1.1 | 按 UHFReader18 协议与读写器通信：组帧、CRC16 校验、收发 | `uhf_reader.py: build_command() / crc16() / transact()` |
| FR-1.2 | 发送询查命令读取标签 EPC，作为卡号 | `uhf_reader.py: UHFReader18.inventory()` |
| FR-1.3 | 支持读取读写器信息以"握手"确认通信正常 | `uhf_reader.py: UHFReader18.get_reader_info()` |
| FR-1.4 | 支持切换"用 EPC 或 TID 作为卡号" | 设置项 `use_tid`；`CardReaderThread(use_tid=...)` |
| FR-1.5 | 后台线程循环询查，不阻塞界面 | `uhf_reader.py: CardReaderThread` |
| FR-1.6 | 串口参数可配置（端口/波特率/地址/询查间隔） | 设置项 `serial_port / serial_baud / reader_adr / poll_interval` |

### FR-2 签到签退业务
| 编号 | 需求 | 实现位置 |
|---|---|---|
| FR-2.1 | 识别卡号对应的学生信息 | `attendance.py: Database.get_student_by_card()` |
| FR-2.2 | 当天首次刷卡 → 签到 | `attendance.py: AttendanceService.handle_card()`（`last is None → action='in'`） |
| FR-2.3 | 当天已签到，距上次签到满间隔时间 → 签退 | 同上（`last['action']=='in'` 且 `delta_min >= interval`） |
| FR-2.4 | 签退后再次刷卡 → 重新签到（允许一天多轮进出） | 同上（`last['action']=='out' → 'in'`） |
| FR-2.5 | 签到签退最小间隔可配置（默认 30 分钟） | 设置项 `interval_minutes` |
| FR-2.6 | 打卡记录入库，可查询、可导出 CSV | `Database.add_record() / query_records()`；`AppUI._export_csv()` |

### FR-3 异常处理
| 编号 | 需求 | 实现位置 |
|---|---|---|
| FR-3.1 | 陌生卡/未绑定卡：友好提示，不崩溃，并留痕 | `AttendanceService.handle_card()` → 返回 `UNKNOWN`；`Database.log_unknown()` |
| FR-3.2 | 短时间重复刷卡：防重复录入 | `CardReaderThread.debounce`（读卡层）+ `AttendanceService`（业务层）双重去抖 |
| FR-3.3 | 读写器断开/通信异常：容错不闪退，自动重连 | `CardReaderThread.run()` 的 try/except + 重连循环 |
| FR-3.4 | 脏数据（半截帧、CRC 错误帧）过滤 | `uhf_reader.py: split_frames()`（帧长+CRC 校验）；`normalize_card()/is_valid_card()` |
| FR-3.5 | 无串口/无 pyserial/无 tkinter 时降级不崩 | `attendance.py` 上方的 try/except 导入；`_start_reader()` |

### FR-4 界面与数据管理
| 编号 | 需求 | 实现位置 |
|---|---|---|
| FR-4.1 | 打卡台：实时显示结果、今日概览、日志 | `AppUI._build_scan_tab()` |
| FR-4.2 | 学生管理：增删改查、刷卡绑定卡号 | `AppUI._build_stu_tab()` / `StudentDialog` |
| FR-4.3 | 历史记录：按日期/关键字查询 | `AppUI._build_hist_tab()` |
| FR-4.4 | 设置：全部参数可视化配置，存库 | `AppUI._build_set_tab()` |
| FR-4.5 | 一键读卡诊断，辅助排障 | `读卡诊断.py` |

## 4. 非功能需求（NFR）

| 编号 | 类别 | 要求 | 实现/证据 |
|---|---|---|---|
| NFR-1 | 可靠性 | 读写器掉线可自动恢复，程序不退出 | `CardReaderThread` 重连循环；`reconnect_seconds` |
| NFR-2 | 可靠性 | 单次刷卡只产生一条有效记录 | 双层去抖（`debounce_seconds`） |
| NFR-3 | 性能 | 刷卡识别延迟 ≤ 约 1.5 秒（受读写器询查时间影响） | 询查间隔 `poll_interval` 默认 0.15s；读写器 Scntm 默认 1s |
| NFR-4 | 易用性 | 开箱即用，图形界面，中文提示 | tkinter 界面；`启动程序.bat` 自动装依赖 |
| NFR-5 | 可维护性 | 分层清晰（协议层/业务层/界面层分离） | `uhf_reader.py`（协议）与 `attendance.py`（业务+界面）解耦 |
| NFR-6 | 可移植性 | 无三方数据库、无重型框架 | SQLite + tkinter，均 Python 自带 |
| NFR-7 | 可测试性 | 无硬件也能跑逻辑与协议自检 | `attendance.py --selftest`；`python uhf_reader.py` |

## 5. 数据设计（与代码一致）

数据库：SQLite，文件 `attendance.db`，定义见 `attendance.py: SCHEMA_SQL`。

### students（学生表）
| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | INTEGER | PK, AUTOINCREMENT | 自增代理主键 |
| student_no | TEXT | NOT NULL, UNIQUE | 学号（业务主键） |
| name | TEXT | NOT NULL | 姓名 |
| class_name | TEXT | | 班级 |
| card_no | TEXT | UNIQUE | 绑定卡号（EPC，唯一） |
| created_at | TEXT | NOT NULL | 建档时间 |

### attendance（打卡记录表）
| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | INTEGER | PK, AUTOINCREMENT | 自增主键 |
| student_id | INTEGER | | 关联 students.id |
| student_no / student_name / class_name | TEXT | | **快照冗余**，学生被改/删后历史仍可读 |
| card_no | TEXT | NOT NULL | 刷卡卡号 |
| action | TEXT | CHECK(in/out) | 签到 / 签退 |
| ts | TEXT | NOT NULL | 完整时间 |
| day | TEXT | NOT NULL | 日期（便于按天查询、建索引） |

索引：`idx_att_day(day)`、`idx_att_stu_day(student_id, day)`、`idx_stu_card(card_no)`。

### unknown_cards（陌生卡日志）
id / card_no / ts —— 未绑定卡刷卡时留痕，用于异常用例举证。

### settings（配置表，key-value）
`interval_minutes / debounce_seconds / reader_mode / serial_port / serial_baud /
reader_adr / use_tid / poll_interval / reconnect_seconds`

## 6. 运行环境

| 项 | 要求 |
|---|---|
| 操作系统 | Windows 10/11 |
| Python | 3.8 及以上 |
| 依赖 | pyserial —— **已内置在项目 `_vendor/serial`**，程序自动加载，无需 `pip install`、无需联网（见下） |
| 硬件 | KL9007U 读写器 + UHF 电子标签 + USB 数据线 |
| 驱动 | CP210x 或 CH340 USB 转串口驱动（开发包附带；本机实测为 CH340） |

### 6.1 非功能需求补充：依赖可移植性（对应 R6 风险）

**问题**：Windows 电脑上常同时存在多个 Python 解释器，`pip install pyserial` 只会装进其中
一个；若程序被另一个解释器启动，就会出现"明明装了却提示未安装"。这不是代码 bug，
而是**依赖解析环境与实际运行环境不一致**。

**对策**：

| 编号 | 需求 | 实现 |
|---|---|---|
| NFR-08 | 串口依赖必须随项目分发，不依赖目标机器是否联网/是否装过 | pyserial 源码内置到 `_vendor/serial`，`_import_serial()` 在 `import serial` 失败时把 `_vendor` 插入 `sys.path` 重试 |
| NFR-09 | 依赖异常时必须可诊断 | 设置页显示「当前实际使用的 Python 路径 + 串口库来源 + 已检测到的串口」；提供 `env_check.py` 与 `环境自检.bat` |
| NFR-10 | 依赖异常时必须可自恢复 | 设置页提供「🔄 重新检测依赖」「🛠 一键安装 pyserial（联网）」两个按钮，后者对**当前正在运行的解释器**执行 pip |
| NFR-11 | 依赖异常时不得崩溃 | 全部可选依赖以 `try/except` 包裹，缺失时降级为键盘模拟模式并在界面用红色明确提示 |
